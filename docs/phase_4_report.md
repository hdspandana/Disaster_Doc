# Phase 4 Report — Typed Evidence Contract and Deterministic Reason Codes

## Objective

Make field results explicit, typed, versioned, and auditable—what was observed, what evidence was evaluated, what was claimed, and why a claim or abstention occurred—without changing the deterministic classifier's verdict rules or beginning Phase 5.

## Existing evidence structures

- `Observation` holds verbatim OCR text, original-image bbox/polygon, and engine confidence.
- `MappedField` groups observations into a template field.
- `FieldResult` owns status, claim, raw text, damage measurements, evidence, and explanations.
- `DamageMap` and the existing adjacent-damage helper supply the field-local signals.
- `EvidenceDocument` assembles raw OCR, field results, audit/processing data, and verification tasks. `report.py` serializes it to JSON and PDF.
- AI is downstream and attaches into `ai_commentary`; current guardrails already prevent factual writes.

## Design decisions

1. Added explicit `observed_value` and `claimed_value` access while retaining the old `raw_ocr_text` and `value` interfaces and JSON keys.
2. Reused `Observation` for typed, field-mapped OCR evidence. Added small `ValidationEvidence` and `DamageEvidence` dataclasses rather than a new parallel evidence framework or validation module.
3. Added a stable `ReasonCode` enum beside the deterministic classifier. Existing detailed `reasons` remain unchanged for compatibility; reason codes and fixed descriptions are the machine-readable primary explanation.
4. Recorded current validation checks as `PASS` / `FAIL` / `UNKNOWN`; checks skipped because no usable OCR was available are `UNKNOWN`, not fabricated passes.
5. Marked local damage evidence as evaluated or not evaluated. In canonical `damage_evidence`, unmeasured ratios serialize as `null`; legacy numeric ratio aliases remain for compatibility and must be treated as unavailable when `evaluated=false`.
6. Added evidence-schema, configuration, and template version metadata. The existing static `CODE_VERSION` remains unchanged; config/template version bump rules are documented.
7. Kept all status, threshold, and claim assignment logic intact. JSON changes are additive; PDF now separates observed text from claimed text.

## Evidence contract

Production JSON documents now include:

```text
evidence_schema_version = 1
metadata = {
  code_version: existing application version,
  config_version: "disasterdoc-config-v1",
  template_version: "1",
  template: "synthetic_id_v1",
  ocr_engine: configured label when available
}
```

Each serialized field includes canonical keys:

- `observed_value`: joined text mapped from OCR observations before classifier usability filtering, or `null` when no text was mapped.
- `claimed_value`: deterministic reported claim; set only for `RECOVERED` under the existing rules.
- `status`: one of the existing three statuses.
- `reason_codes` and `reason_descriptions`.
- `ocr_evidence`: mapped OCR observation IDs, observed text, confidence, bbox, polygon, and usability flag.
- `damage_evidence`: field/adjacent boxes and ratios, with an `evaluated` flag. Ratios are `null` when not evaluated; use this typed record instead of interpreting legacy ratio defaults.
- `validation_evidence`: named current checks with PASS/FAIL/UNKNOWN and details.

`value`, `raw_ocr_text`, `evidence`, and `deterministic_reasons` remain as legacy aliases/details. `observed_value` and `claimed_value` remain separate keys even when their strings match. Full JSON structure and migration notes are in `docs/evidence_contract.md`.

## Reason codes

The Phase 4 code set is:

1. `OCR_UNAVAILABLE`
2. `NO_FIELD_OBSERVATION`
3. `NO_USABLE_OBSERVATION`
4. `LOW_OCR_CONFIDENCE`
5. `INSUFFICIENT_TEXT`
6. `MINIMUM_CHARACTER_COUNT_FAILED`
7. `MINIMUM_TOKEN_COUNT_FAILED`
8. `FORMAT_INVALID`
9. `TRUNCATED_OBSERVATION`
10. `VALIDATION_FAILED`
11. `ADJACENT_OBSCURATION`
12. `HIGH_LOCAL_DAMAGE`
13. `INSUFFICIENT_EVIDENCE`
14. `RECOVERY_GATES_PASSED`

Codes are emitted in fixed check order. They correspond to the existing classifier gates; no new check is implied by them. No `RECOGNITION_DISAGREEMENT` code is emitted because multi-pass/independent recognition does not exist. Free-text details remain available but are no longer the sole machine-readable reason representation.

## Invariants

- `PARTIAL` → `claimed_value=None` and legacy `value=None`.
- `UNRECOVERABLE` → `claimed_value=None` and legacy `value=None`.
- A non-null claim on either non-recovered status is rejected at construction/serialization.
- `RECOVERED` may report the OCR-derived claim; observation and claim remain semantically distinct.
- Only the existing status values `RECOVERED`, `PARTIAL`, and `UNRECOVERABLE` are used.
- Ground truth is not a production field, classifier input, pipeline value, evidence field, UI decision, or PDF decision. It remains in evaluation artifacts only.
- OCR confidence is an engine score; the existing heuristic `confidence_bucket` is not a calibrated probability or a newly invented evidence score.
- Human verification remains separate from deterministic evidence and does not rewrite it.

## AI boundary

The guardrail denylist now covers observed/claimed values, legacy aliases, statuses, reason codes/descriptions, OCR evidence, validation and damage evidence, confidence/geometry, version metadata, and a ground-truth key. Rejected fields are logged by key, not by their supplied values. The regression test attempts to overwrite each deterministic category and confirms the serialized deterministic result is unchanged.

## Compatibility

- Internal consumers can continue using `FieldResult.value`, `raw_ocr_text`, and the existing `evidence` list. The prior dataclass positional constructor order is retained.
- JSON keeps those legacy keys and adds explicit canonical fields/version metadata; summaries, verification tasks, processing data, and raw OCR remain.
- PDF keeps its existing safe export path but now labels Observed, Claimed, and Status independently. An abstention prints “Not claimed,” not the observed fragment as a value.
- The Phase 2 results snapshot was refreshed only because its recorded classifier/config source hashes changed. Case-level results and summary counts were verified unchanged.
- Phase 3 image-level artifacts retain their original source hashes and saved outcomes as the historical Phase 3 run; no Phase 3 methodology or artifact was regenerated.

## Limitations

- `observed_value` is a field-mapped OCR aggregation; the individual verbatim `Observation` records are the authoritative per-box evidence.
- Current validation remains shape-based. No calendar-valid DOB check, semantic truth validation, checksum, recognition agreement, or independent OCR signal was added.
- The configured OCR-engine label is recorded, but the production pipeline does not expose the installed OCR package/model version; no value is invented.
- The existing static `CODE_VERSION` remains `disasterdoc-0.1.0`; schema/config/template versions distinguish this contract/configuration but do not replace a source-control revision.
- Reason-code correctness is bounded by the classifier's existing checks; passing them is not proof of correctness. Phase 3 remains a small synthetic one-template pilot, not a real-world estimate.

## What was intentionally NOT changed

- No classifier thresholds, check conditions, output statuses, or `PARTIAL` / `UNRECOVERABLE` null-claim semantics.
- No OCR engine, second OCR pass, recognition consistency, validation strengthening, trained model, or LLM recovery.
- No UI redesign, database, authentication, benchmark expansion, calibration, risk-coverage analysis, or Phase 5 implementation.
- No Phase 3 rerun, data edits, or methodology change.

## Phase 5 recommendation

After review, consider narrowly scoped field-specific validators (for example, calendar validity for DOB) as additional evidence only. Evaluate their impact separately before any classifier behavior change, retain the observed/claimed distinction and null-claim invariants, and do not treat a format/semantic validator as source truth. No Phase 5 work is included here.
